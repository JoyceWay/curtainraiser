## 📐 1. `data.js` 严格字段契约（Schema Contract — 缺一不可，字段名严禁拼错）
`window.HISTORICAL_EVENTS` 数组中的每个事件对象，必须严格包含以下字段，`index.html` 也必须严格按这些字段名读取：
```js
{
  id: "hammurabi", // string
  title: "Code of Hammurabi", // string
  year: "1754 BC", // string
  place: "Babylon, Mesopotamia", // string
  mapX: 58, // number (0-100 SVG 地图横坐标百分比)
  mapY: 42, // number (0-100 SVG 地图纵坐标百分比)
  story: [
    "Paragraph 1...", // 必须包含 2 段英文，每段不少于 80 个英文单词！故事中用 <span class="sat-word" data-word="codify">codify</span> 高亮嵌入对应的 SAT 词
    "Paragraph 2..."
  ],
  satWords: [ // 必须包含 2 个对象
    { word: "codify", pos: "v.", definition: "arrange laws or rules into a systematic code", example: "Hammurabi decided to codify the chaotic rules of Babylon into stone." },
    { word: "retaliation", pos: "n.", definition: "the action of returning a military attack; counterattack or revenge", example: "The law of 'an eye for an eye' was built on the principle of exact retaliation." }
  ],
  groupChat: [ // 必须包含 3 条仿 iMessage 幽默群聊，每条不少于 1 个完整且戳中 12 岁初中生笑点的英文梗
    { sender: "King Hammurabi 👑", text: "..." }, // 注释注明：(参照梗 #X)
    { sender: "Babylonian Builder 🧱", text: "..." }, // 注释注明：(参照梗 #X)
    { sender: "Royal Scribe 🪶", text: "..." } // 注释注明：(参照梗 #X)
  ],
  trivia: "Did you know? ...", // string (真实有趣的历史冷八卦，不少于 2 句话)
  takeaways: { // 每项不少于 2 句完整的 AP 历史级准确解析
    cause: "...",
    turningPoint: "...",
    impact: "..."
  },
  quiz: [ // 必须包含 2 道四选一题（Q1考历史因果，Q2考本篇 SAT 词 codify 或 retaliation 的语境词义）
    { question: "...", options: ["A...", "B...", "C...", "D..."], answerIndex: 1, explain: "..." },
    { question: "...", options: ["A...", "B...", "C...", "D..."], answerIndex: 2, explain: "..." }
  ],
  stampName: "👑 King Poppy of Babylon" // string
}
```

## 💾 2. localStorage 状态持久化契约（防刷新丢失）
所有玩家进度必须实时存入 localStorage（使用统一键名 LIVING_HISTORY_SAVE_V1），确保刷新页面或重新打开浏览器绝不丢失：
- coins: Chrono-Coins 余额（初始值 0）
- unlockedWords: 已点击收集的 SAT 单词数组（防止重复刷币，每个单词仅首次点击奖励 +10 🪙）
- unlockedTrivia: 已翻转过的冷八卦事件 ID 数组（每个仅首次翻转奖励 +10 🪙）
- completedEvents: 已通关的地图金星事件 ID 数组（首次无伤通关两道题奖励 +50 🪙）
- stamps: 已解锁的猫咪印章名称数组
- hasShield: 是否已购买激活答错保护盾（boolean）

📜 合同 v2

双 AI 使用合同（Muse × Gemini）

0. 一句话原则

  • Muse 有记忆、做终审；Gemini 没记忆、做参谋。你只做 1%：定目标、做选择、验收。

1. 分级——什么事走什么流程

  • L1 小事（查词、翻译、简单解释）：直接问 Muse，不用 Gemini
  • L2 中事（写卡片、改文案、日常分析）：Muse 独立做，你验收
  • L3 大事（写代码 prompt、定架构、发版前检查）：走完整双 AI 会诊
  • 紧急模式：赶时间跳过 Gemini，Muse 直接做你验收，事后再补

2. 标准 Loop（L3）

  • 你定目标（一句话）→ Muse 出初版 → 你转交 Gemini → Gemini 输出 → 你转回给 Muse → Muse 终审（双方观点+证据+判断）→ 你拍板 → 执行 → Muse 验收（对照最初那句话逐条打勾）

3. 上下文包模板（给 Gemini 的固定格式）

【目标】一句话说清要什么
【硬约束】1. 2. 3.（上限 5 条，多了它记不住）
【当前版本全文】（粘贴 Muse 的初版）
【请你做的事】审查 / 补强 / 重写（三选一）
【具体问题】你最担心的 1-2 个点

4. 分歧处理

  • Muse 和 Gemini 不一致时，Muse 不和稀泥，直接摆出：他的观点+证据 / 我的观点+证据 / 我的判断+理由，然后你拍板。

5. Gemini 已知坑清单（活的，发现就追加）

  • 会编流行梗 → 必须加"找不到就说没找到，不许编"
  • 会把内部标注写进 UI → 标注只放代码注释
  • 战略问题会一本正经瞎答 → 它的战略意见只当参谋，决策权在 Muse

6. 合同本身是活的

  • 版本号 v1/v2……每发现一个新坑或新分工，Muse 追加一条。你只管用，维护是 Muse 的活。

7. 成本

  • 你的时间只花在两处："转交"（复制粘贴，1 分钟）和"拍板"。其他全 Muse 包。
