01 · Jason Wei — “会做什么”的没落与“你认识谁”的崛起

原文：Jason Wei《The fall of "what you can do" and the rise of "who you know"》，2026-11-11 · 原文链接 ↗ · 状态：已翻完

传统上，我们很多人相信这样一个世界：你多努力，比你认识谁更重要。我曾经也信奉这个观念——既作为一名科学家，相信关于这个世界的事实与“是谁说的”无关；也作为一个美国人，从小相信成功取决于你多努力，而不是你认识谁。

但现在，我在 AI 领域感受到一个实质性的变化，尤其是在过去五年里：“你认识谁”变得越来越重要，“你会做什么”则变得没那么重要。我当然不是说技术能力不重要，或者说没有人脉就无法成功。技术能力依然重要，甚至决定你的职业生涯。但我注意到一个趋势。如果给个大概的数字，我会说，五年前，成功 75% 靠你的能力，25% 靠你认识谁。现在，大概是 55% 靠能力，45% 靠你认识谁。

这个趋势背后有三个技术原因。第一是智能的商品化（commoditization of intelligence）—— coding agent（编程智能体）基本上让研究执行民主化了。过去，你可以通过熬夜调代码、更频繁地盯着实验来甩开竞争对手。现在，很多研究任务只要知道该输入什么提示词，谁都能完成。研究品味（research taste）当然依然重要，但竞争环境确实变得更公平了。当技术执行不再是区分彼此的关键，其他优势自然就变得更重要了。

第二个原因是，随着语言模型规模化（scaling）的成功，资源丰富让你更容易成功，这已经是个事实。十年前，一个拥有 8 张 GPU 的学术实验室完全有机会做出出色的研究。现在，一次 RL（强化学习）训练就可能需要几百张（甚至几千张）GPU，还有大量的数据和基础设施。所以现在，两个能力相当的研究者，成果可能天差地别，取决于他们手里有什么资源。而能不能拿到这些资源，不只取决于技术能力，还取决于声誉、与决策者之间建立的信任，以及职业关系。这些东西一直都很重要，但随着前沿 AI 对资源的需求越来越大，它们的重要性也在水涨船高。

第三，当公司不再发表研究、转向保密的闭源模型，AI 成了一个可观测性（observability）很差的领域。在象棋或足球这类可观测性完美的领域，很容易看出来谁表现出色、谁做了什么贡献。但现在 AI 领域公开归属功劳的机制越来越少，外人很难知道一次模型发布背后到底是谁做了什么。那这个问题怎么解决？当一个人的技术贡献难以被独立验证时，人们越来越依赖间接信号，比如声誉、个人背书，以及谁愿意为你担保。于是，“你认识谁”在招聘、招募和融资中扮演的角色就大得多。

我们经常谈论如何提高技术能力，却很少有人谈论如何提升“你认识谁”。我的一个观察是，很多有人脉的人把工作和生活混在一起。传统智慧是两者之间要划清界限，这在过去是非常合理的策略。但现在，社交的回报变高了，这意味着还坚持划清界限的人，付出的代价比以前大得多。

Sam Altman 就是一个工作生活不分家、人脉极广的典型例子。他身上有很多值得学习的地方。比如，OpenAI 还很小的时候，Sam 就邀请几乎所有员工到他家里参加社交活动。他还在家里办扑克之夜和晚宴，目的就是招人。Sam 以慷慨待人、善待朋友而闻名，我认为这给他带来了不成比例的回报。当然，OpenAI 内部的人际关系并非都一帆风顺，但我认为 OpenAI 的成功很大程度上来自 Sam 的人脉。

有意思的是，刻意努力去结识人，可能并不是最优策略。我不认为 Sam 结交人脉是因为他知道这会在职业生涯中得到回报，而是因为他天生就是一个慷慨的人，对人和技术有着天生的好奇心。也许最好的策略就是做最好、最真实的自己——说起来容易做起来难，尤其是在一个技术不断变化的世界里。

虽然这些技术趋势让这个领域对技术实力的依赖变小了，但我并不认为这一定是坏事，而且这也不是我们这个领域第一次发生这种事。比如，Python 引入的抽象（abstraction）也让编程变得不那么技术化，让更多人能写代码。而且对某些技能组合来说，现在的机会比以往任何时候都多。比如，没有编程背景的人现在也能做出很棒的技术产品，产品品味或研究品味成了更关键的杠杆。所以，虽然“我们能做什么”被商品化了，但“我们选择做什么”以及“和谁一起做”，将比以往任何时候都重要。

原文金句：“So while what we can do is commoditized, what we choose to do, and who we do it with will matter more than ever.”

02 · Andrew Ng — 用开源 OpenWorker Agent Harness SDK，为任意大模型搭建 agent harness

原文：Andrew Ng，The Batch 第 379 期，2026-11-13 · 原文链接 ↗ · 状态：已翻完

一、为什么现在要学搭 harness

亲爱的朋友们，

搭建 agent harness（智能体脚手架）已经成为构建 AI 智能体的一种快速流行的方法。OpenWorker 项目刚刚发布了开源的 OpenWorker Agent Harness SDK，邀请大家去看看。如果你以前没有搭建过 agent harness，我鼓励你动手试一次。（这项技能已经写进了《AI 工程技能图谱》（AI Engineering Skills Map），而且面试里越来越多地会问你有没有做过这件事。）这封信要讲的，就是如何指挥编程智能体（coding agent），快速搭建出一个 agent harness。

二、agent harness 到底是什么

所谓 agent harness，就是包在大模型外面的一层代码，它给大模型提供上下文（context）、工具（tools）和护栏（guardrails），把它变成一个真正的应用。

从去年年底以来，大模型已经强大到这个程度：很多应用都可以靠反复调用大模型、让它自己决定下一步做什么来搭建。比如，你可以给它一组工具（函数）——读 / 存文件、跑 shell 命令、执行它自己写出来的代码、读取执行结果——来打造属于你自己的编程智能体。有了这些工具，你就能做出一个简单的编程智能体：把代码存进文件，跑起来，看看有没有报错，再一轮一轮迭代改进。

三、动手：搭一个整理文件的演示智能体

再举第二个例子：下面是如何搭建一个整理文件的小演示智能体。首先，在一个新的空项目目录里，在 bash 中运行：

npx @openworkerai/openworker-harness-builder --agent claude --project .

如果你的编程智能体是 Codex，就把上面的 claude 换成 codex。这一步会在当前目录安装 OpenWorker 的 openworker-harness-builder。然后，给你的编程智能体下这样一段提示词：

Use the openworker-harness-builder skill to build a small local file-organizing agent using the OpenWorker Harness SDK. Generate 10 sample text files in a dedicated demo directory. The app should have an agent that has tools to list and read files, create/delete subdirectories, and move files. Configure the harness such that all of these tools are restricted to only the demo directory. Use OPENAI_API_KEY in ~/.env and gpt-6.1-terra [or ANTHROPIC_API_KEY and claude-sonnet-5-5]. Prompt the agent to organize files, create subdirectories, and move files into appropriate subdirectories to organize the files. Require user approval before each subdirectory creation and file move, showing the proposed operation. Display tool activity so the user can see what happens at each step of the demo. As it is running, also display a succinct description of the status of the agent loop so the user can see what's happening.

提示词要点（我的说明，不是原文）：用 OpenWorker Harness SDK 搭一个本地整理文件的小智能体；生成 10 个示例文本文件；所有工具只能动演示目录；每次建子目录、移文件之前都要用户批准，并展示拟执行的操作；全程显示工具活动和 agent loop 的状态。

四、长期运行的智能体还要管什么

搭建 agent harness，需要管理大模型的上下文。对于长时间运行的智能体，这意味着要搭建一套记忆架构（比如上下文太长时做记忆压缩（memory compaction））。一个 harness 可能还需要护栏（比如输入 / 输出检查）、审批机制、安全控制（比如不让凭证碰到大模型），以及沙箱隔离（sandboxing）。

OpenWorker Desktop 已经在许多安全工作流里用起来了，我和 Rohit Prsad 打造 OpenWorker Harness SDK，本来是为了更方便地改进 OpenWorker Desktop。但让我们惊喜的是，好几个其他团队也发现 Harness SDK 对搭建别的智能体很有用，所以我们决定把它开源。你可以用它搭建本地运行的智能体，也可以搭建部署到线上的智能体。

五、为什么选开源的 OpenWorker

如果你还没有搭建过 agent harness，请按上面的步骤试一次。和模型厂商提供的 agent harness 工具不同，OpenWorker 的 Harness SDK 是开源的，不绑任何一家模型，所以你可以轻松搭建出能在任意模型厂商、任意云上运行的智能体。

继续搭建吧！ Keep building!

—— 吴恩达（Andrew Ng）

来源：Km @Zkm211，X，2026-11-15 · 原帖链接 ↗ · 132.7K 浏览 · 2,020 收藏 · 价值：8/10

小红书小工具正在内测买断和内购，后续还能接广告变现。路子和微信小程序差不多，但小红书这边还是蓝海，而且平台对小工具相关的帖子有很大的流量激励。

例子：朋友的游戏《好雨时节》上架几个小时，¥14 卖了 18 份（约 ¥252），用薯币支付。玩法很简单：把 Claude 做的游戏直接移植到小红书，小红书配好了 Agent 协作工具，全程 AI 能做完。评论里也有人说上架很简单，只要代码合规，没其他门槛。

对我们的意义：妈妈号的分发 + 年底前第一笔收入的新路子。单词卡和小游戏移植过去要先核实：英文 SAT 内容是否适合小红书小工具的受众、支付与合规怎么走。
